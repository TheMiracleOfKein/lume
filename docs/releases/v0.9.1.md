# Lume v0.9.1

Lume can now keep an eye on folders on your phone and bring in new chapters by itself.

## New

- **Watched folders.** Settings → Library → Local files → Add a watched folder. Pick a folder with your series (image folders, CBZ, CBR, CB7 or PDF), and Lume imports it into the local library like "Import folder" does.
- **Scan now and a scan interval.** Tap "Scan now", or let Lume check the folders every 6, 12 or 24 hours (or never). Only new and changed files are copied, so a scan with nothing new is quick and adds nothing twice. A file replaced with a newer version is copied again.
- **"N new chapters".** When a scan finds new chapters, Lume says so through the library update notification. Notifications must be allowed for Lume.
- **Reconnect.** If Lume loses access to a folder (it was moved, deleted or its permission was removed), the folder says so and offers "Reconnect" to pick it again.
- Removing a watched folder stops the scans. Chapters already copied stay in the library.

## Updating

Install it over v0.9.0 as usual. Your library, progress, bookmarks and downloads are kept. The database gets two new tables for watched folders and the list of files already imported; nothing existing changes.

## For developers

- Room 13: `watched_folders(treeUri, label, addedAt, lastScanAt, available)` and the `imported_files` ledger (`treeUri`, `documentId`, size, last modified, destination path). Additive migration in `LumeDatabase.MIGRATIONS`, schema in `app/schemas`, covered by `MigrationTest`.
- `LocalImporter` takes the ledger and skips documents whose size and modified time are unchanged; it returns the new chapters per title.
- `FolderScanWorker` (`CoroutineWorker`): periodic work at the chosen interval plus a one-time "Scan now" request, scheduled from `AppContainer.start()`. Persistable tree permissions are taken on add and released on remove; a lost permission sets `available = false`.
- New tests: the ledger diff test and the 12→13 migration.
- Device check: [v0.9.1-check.md](v0.9.1-check.md). Not tried on the device: the 12→13 upgrade, revoking access and "Reconnect", and a background scan on its schedule.
