# Lume v1.0.0 pre-release check

Branch: release/v1.0.0 (HEAD 4fe7d1f), compared with tag v0.9.16 (24 commits).
Device: emulator-5554, debug builds of the `full` and `manga` flavors.
No source edited, nothing committed or pushed. Emulator left running; the `full` build was replaced by the `manga` build at the end.

## Changed areas
1. Module split (:core:common, :core:model, :core:data, :core:ui, :feature:comics, :feature:novel, :app). Local comic files moved into :feature:comics.
2. Two flavors: `full` (comics + novel) and `manga` (comics only). The novel module is a preview with no engines.
3. MediaKind abstraction and DB migration 15 to 16 (bookmarks.mediaKind, reading_progress.mediaKind). Library and History are filtered by the active mode.
4. Active mode preference. Mode switcher: long press on the middle logo of the bottom bar, the logo of the NavRail on wide screens, or the "Mode" entry in the main menu. Hidden in the manga flavor.
5. Ranobe mode shows a coming-soon state on Home, Catalog, Updates and Search.
6. AppUpdater takes the APK of the build's flavor (code only; not exercised, no release published).

## Problems found

### Serious
None observed. No crash, no broken navigation, no layout break, no data loss in the walked paths.

### Minor
1. **Library in Ranobe mode shows the generic empty state, not the coming-soon state.** Steps: full build, switch to Ranobe, tap Library. It reads "Your library is empty" with the normal filter chips. Code: core/ui/src/main/java/com/lume/app/ui/shell/AppShell.kt, the `Routes.Library` destination (around line 216) is not wrapped in `ModeGate`, unlike Home, Catalog, Updates and Search. The data is correct (the library is filtered by mode); only the empty state differs from the other preview screens.
2. **Sources is not filtered by mode.** Steps: full build, switch to Ranobe, Menu → Source. The Sources screen still lists every comics source (MangaDex, MangaKatana, Asura, Local, ...), and the menu row still shows the active comics source ("MangaKatana"). The release notes list Sources among the filtered screens. Code: core/ui/src/main/java/com/lume/app/ui/screens/ManageViewModels.kt, `SourcesViewModel` (around line 644) exposes `app.sources.sources` unfiltered. Decide whether Sources should be filtered or the notes should change.
3. **Not walked, code has no mode gate or filter:** Downloads (AppShell.kt, around line 241), Stats (around line 244), Categories and Reading list. Expected to show the same content in both modes; check in Ranobe mode before release.
4. **Predictive back is not enabled.** Logcat warns: "OnBackInvokedCallback is not enabled for the application". Pre-existing, informational.
