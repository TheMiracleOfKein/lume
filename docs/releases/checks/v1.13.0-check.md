# Lume v1.13.0 pre-release check

Branch: `feat/remote-source-hosts`. Build: `app/build/outputs/apk/full/debug/app-full-debug.apk` (debug, full flavour). Device: emulator `Lume_Light` (API 34), Wi-Fi disabled, mobile data.

## Changed areas

- Remote source-address list: `docs/packs/hosts.json` (new, on this branch only), fetched by `core/data/.../data/source/SourceHosts.kt`, applied by `core/model/.../domain/HostOverrides.kt` and `core/data/.../data/source/SourceRegistry.kt`.
- Fallback to another host when one fails: `core/data/.../data/network/HostFallback.kt`, wired in `AppContainer.kt` and `AppHttp.kt`.
- New Settings → Network and storage → "Update source addresses" toggle (`SettingsCatalog.kt`, `SimpleSettingsPages.kt`, `AppPreferences.kt`, EN and RU strings).

## Failed / observations

1. **Remote hosts file is not fetched yet (expected before merge).** `docs/packs/hosts.json` does not exist on `main`, so the default URL (`raw.githubusercontent.com/.../main/docs/packs/hosts.json`) and the jsDelivr mirror both return 404 until this branch is merged. After launch, `files/hosts.json` was not created in the app data, and the datastore only holds the `remote_hosts` key (no `hosts_fetched_at` is visible). This is consistent with the fetch failing silently, not a bug in the toggle itself.
   - Gap: `SourceHosts.refresh` swallows failures with `runCatching` and logs nothing, so a broken or missing hosts file is invisible in logcat. Consider a debug/warn log line there.
   - Re-check after merge: force-stop, relaunch, confirm `files/hosts.json` appears (debug build: `run-as com.lume.app`).
2. **Host fallback not exercised.** No host failed during the walk, so the fallback path in `HostFallbackInterceptor` did not run on the device. Covered only by the JVM tests (`HostFallbackTest`, `HostOverridesTest`).

## Not checked

- MangaDex-type source catalog and title (no MangaDex-type source was opened; the Asura Scans home source was only used for the home screen).
- A source that is region-blocked or behind Cloudflare (none tried).
- Remote hosts list applied to a real moved address (needs the file on `main`).
- Landscape reader; reader settings beyond opening the reader.
- Release APK (R8) — only the debug build was tested here; the release smoke test is part of the release path.

## Verdict

No crash, no `FATAL EXCEPTION`, catalog, title, reader, toggle persistence, rotation and RU strings all pass. No blocking problem found. The hosts-file fetch is inactive until the file reaches `main`, and its failures are silent (see item 1).
