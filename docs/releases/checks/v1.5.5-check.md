# v1.5.5 pre-release check: guided panel view

Branch `feat/guided-panels`, compared with tag `v1.5.4`. Debug build `app-full-debug.apk`, emulator `Lume_Light` (API 34), driven with mobile-mcp.

## Changed areas

- `feature/comics/.../ui/screens/ReaderPaged.kt`: page turns run through `interruptible {}`, so a cancelled animation ends only that turn. Guided steps are keyed by strip item and reset when a page is left behind. Panel order comes from settings, not the page-turn direction.
- `feature/comics/.../ui/screens/ReaderPagedPage.kt`: `PanelSpotlight` draws the 70% black scrim with a hole around the focused panel, following the zoom (`transformedContentBounds`).
- `core/model/.../domain/page/PageAnalysis.kt`: comic panels grow over ink that breaks out of their frame (`withOverflow`), bounded by neighbouring panels and a margin.
- Settings: `AppPreferences`, `ReaderDefaultsSettings`, `SettingsCatalog`, `ReaderSettingsSheet`, strings (EN and RU).

1. Narrow "column" view on page 2 of chapter 337 looked like a layout break at first. Going back to page 1 showed the cover full width, and the column was the tall strip image fitted to screen height. Not a bug, but worth remembering when testing with tall pages.

## Possible bug spots (from reading the code)

1. `PageAnalysis.withOverflow`: the flood fill is limited to the margin and excludes other panels' cores, but it does not exclude other panels' overflow. Two overflow boxes can still overlap, and the bounding box of the overflow can grow over a neighbouring panel's area, so the focus order or zoom can take in the wrong art.
2. `minOverflowPixels = 4` is very small. A few stray specks in a gutter can extend a panel's box to include them, which widens the zoom.
3. `PanelSpotlight` positions the hole from `transformedContentBounds` (deprecated API) and the fractions from the analysis. If a page is ever drawn with a cropped region (`pageRegion`), the hole would be offset. Guided view currently disables crop and split parts, but any future change to those paths breaks the dim silently.
4. `PanelSpotlight` keeps the last panel in a plain `arrayOfNulls` written during composition; the dim-out uses it. Works, but not state-driven, so a recomposition without a state change can show a stale hole during the fade.
5. `stepPanel` returns false when the zoom is not measured yet, so the first tap turns the page instead of focusing. Intentional, but on a slow first load a tap can skip a page's panels.
6. `interruptible` catches `CancellationException` around the whole turn and rethrows only when the coroutine is cancelled. A cancellation from a page change that is not a reader shutdown is swallowed, so the turn ends silently; intended, but worth a test with rapid mode switches.
7. `zoomStates` and `steps` are keyed by strip item key. Items that share a key (a split page and its parts) could share a step entry; the code assumes keys are unique per part.

## Verdict

SERIOUS problems (crash, taps stop working, broken layout): **no**. No fatal exceptions, taps kept working through rapid taps and mid-animation swipes, the dim renders at the expected strength and follows the focused panel, and turning guided view off restores plain page turns. Remaining gaps are the visual panel-order check (f) and RTL detail (e), listed above.

Nothing was committed. Emulator Wi-Fi was disabled for the test.
