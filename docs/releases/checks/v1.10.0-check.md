# Lume v1.10.0 pre-release check

Branch: feat/ai-settings (HEAD ab9f9bb). Device: emulator Lume_Light (API 34, 720x1600), driven with mobile-mcp; adb used only for setup (Wi-Fi off, install, launch) and logcat.
Build under test: `app/build/outputs/apk/full/debug/app-full-debug.apk` (debug, full flavor).

**Build:** the APK was built from the final working tree; the feature commits were made afterwards from the same files, so the commit times are later than the APK but the code is the same.

**After this check:** finding 1 is fixed. When the active service has no key, the sheet now also shows the "AI and translation settings" button.

## Passed
1. **AI and translation settings page (Ranobe mode).**
   - Settings list shows "AI and translation" next to Reader. Opens with the active-service list: OpenRouter, OpenAI, DeepSeek, Gemini, Own server, each "No key yet".
   - OpenAI with fake key `sk-test-123456`: field shows masked value, check icon saves, "Key saved: ••••3456", then "Checking…", then "The service refused this key · checked 0 minutes ago".
   - "Remove the key" removes it immediately (no confirmation) and status returns to "No key yet".
   - Own server with `http://10.0.2.2:9/v1` saved: "No answer from the service (internet or address) · checked …". The address field and model section ("Automatic") appear.
   - DeepL section: key field, "Get a key at deepl.com", "No key yet", "Check now".
   - Settings search "openrouter" returns "Active AI service", "Model" and "DeepL API key" results. Tapping a result opens the AI page.
   - Choosing a service in the list changes which key section is shown.
2. **Reader translate sheet.**
   - No URL field in any engine section. The only text fields are "Style note" and the glossary, which are not keys.
   - DeepL selected: "Add your DeepL key in Settings → AI and translation first.", "No key yet", "Open AI settings". The button opens the AI settings page and Back returns to the reader at the same position.
   - Google Translate, then "Read in English" switched on: progress "Google Translate: 59 of 77 paragraphs" with a progress bar, then the chapter text is English. The toggle reads on.
3. **Translation on/off persistence.**
   - On, leave reader (Back), reopen the same chapter right away: translation still on.
   - Turn off, leave, reopen: original text.
4. **Recap ("Previously…").**
   - At chapter start: "Nothing to recall yet: you are at the start." with "Continue reading".
   - At 4%: sheet lists the paragraphs before the current spot, with "Continue reading".
5. **Rotation.** Reader in landscape: top bar, progress bar and bottom controls laid out correctly. Returned to portrait without issue.
6. **Regression.**
   - Home loads in Ranobe mode (novel covers) and Manga mode (Overgeared, Asura Scans).
   - Manga mode Settings has no "AI and translation" entry, as intended (Ranobe only).
   - Overgeared, Chapter 0 (Asura): reader opens, page 1 draws, scrolling to page 2 draws.
7. **Crashes.** `logcat -d | grep "FATAL EXCEPTION"` empty after each scenario and at the end (count 0). Only IME and frame-tracker timeouts, no exceptions.

## Findings (none serious)
1. **Translate sheet, AI engine with no working key (minor, wording and CTA differ from the spec).**
   - Selecting "AI (your key)" with OpenRouter active and no key shows "Set up an AI service first: add its key in Settings → AI and translation." and a Service picker. There is no "Open AI settings" button.
   - Selecting the "Own server" chip (a saved address whose last check failed) shows "AI and translation settings", and the message now says "Set up an AI service first" while the picker offers a service.
   - The Read-in switch is not offered for AI until a service works, so the AI failure path could not be reached with a fake key (see Not checked).
   - Steps: Reader → Translate → "AI (your key)" with no working key.
2. **Keyboard covers the Save check icon on the AI key field (possibly emulator-specific).** After typing into the key field the IME is open. Tapping the Save icon position (about x 632, y 1022) opened the keyboard's own theme settings instead. With the keyboard dismissed (Back, not the app's Back) the Save icon works. Check on a physical device.

- **AI failure during translation (Retry and "AI and translation settings"):** requires a working AI service to turn Read-in on. A fake key does not reach a working state, so this could not be tested.

- **Privacy note at the bottom of the AI page:** not read.
- **Language switch and rotation on the AI page:** not tested (optional in the brief).
- **Empty "no service set up" state with no Own server address:** not reached; the Own server address was left saved during the run, so the CTA difference in finding 1 was seen only in that state.
- **MangaKatana chapter:** not used; Asura Scans (Overgeared) was read instead, and its pages drew.
