# Lume v0.9.14

Search and reading-ahead improvements: whole chapters can load in the background while you read, search shows titles whose name matches first, a source's catalogue gets its own search and filters, and the filter sheet no longer shakes when swiped down.

## New

- **Chapters loaded ahead.** In the reader settings (and Settings > Reader), choose **Off**, **1** or **2** chapters. While you read, the next chapters' pages download into the image cache in the background, so turning to them is instant and they keep working if the connection drops for a while. Pages go one at a time with short random pauses, and the loading backs off and stops after repeated errors, so sites with request limits (nginx limits, Cloudflare rules) don't block you. Downloaded chapters are skipped. It is off by default because it uses more data. The "pages loaded ahead" setting works as before.
- **Search inside a source's catalogue.** The catalogue now has a search field and a filter button (genres, status, sort and whatever else the site offers), for that source only. Results replace the tabs; **X** or **Back** returns to them.

## Improved

- **Search results: name matches first.** Sites also return titles that only mention the words in their description or tags. Lume now puts the titles whose name (or alternative name) matches at the top: exact name, then names starting with it, then names containing the words, then the rest in the site's order. This applies to the search screen (one source and all sources) and the new catalogue search.

## Fixed

- **Filter sheet shaking.** Typing in a genre group's **Find** field and then swiping the filter sheet down made it shake endlessly. Dragging the sheet now closes the keyboard first.

## Updating

Install it over v0.9.13 as usual. Your library, progress, bookmarks, downloads and sign-ins are kept. No database change.

## For developers

- Chapters ahead: `ReaderSettings.preloadChapters` (preference `reader_preload_chapters`, 0…2). `ReaderViewModel.preloadChaptersAhead` restarts when the current chapter changes and caches images with `ImageLoader.execute` (disk cache only, skipped when already on disk). Pacing and backoff in `domain/ChapterPreload.kt` (`PreloadPacer`); page lists fetched ahead are reused for 10 minutes, or for good once every image is cached, since image URLs can be signed and expire. A retry fetches the list again.
- Ranking: `domain/SearchRanking.kt` (`nameMatchRank`, `rankSearchResults`), a stable sort that keeps the site's order within each rank.
- Catalogue search: `CatalogViewModel.searchFeed` with its own filters (`prepareFilters`, `applyFilters`, `clearSearch`); cleared when the active source changes.
- `FilterPanel`: `dropFocusOnDrag` watches the initial pointer pass without consuming it.
- Tests: `SearchRankingTest`, `ChapterPreloadTest`.
