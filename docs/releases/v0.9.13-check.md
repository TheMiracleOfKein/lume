# v0.9.13 device check

Date: 2026-11-12

Device: Pixel 6a emulator (AVD model string sdk_gphone16k_x86_64), API 37, 1080x2400.

Tool: adb only (screenshots plus uiautomator dumps). Debug build installed with `install -r` from the debug APK of branch release/v0.9.13 (commit 88a6c6c). Screenshots are kept locally and referred to by file name only.

## Changed areas

- Chapter list: the multi-select bar overlays the list instead of being the bottom bar (bug O17).
- Theme colours for contrast (dark, light, AMOLED); top bars and search field grow with font size; some dialogs scroll; bottom nav labels ellipsize.
- Library: genre filter in the options sheet (Filter tab), genre checkboxes; DB migration 14 to 15 adds genres per title; genres fill when a title is opened.
- MangaLib bookmark import runs as a WorkManager job (not exercised; no account signed in).
- Nearby: send screen shows a QR code; receive screen has "Scan QR code" with a camera rationale.
- Refactors that should behave the same: Home feed, Title header, Settings sections.

## Checked and passed

- Launch: Home loads with Quick search, Continue reading and New releases.
- Catalog (Asura Scans source) opens Overgeared. Title screen shows header, Read, Chapter list (348), Sources, Trackers, genre chips, description and "Similar titles". Add to library works (button switches to "Remove from library").
- Chapter list selection (Overgeared and Nano Machine):
  - Long-press shows the selection bar (Mark read, Mark unread, Mark previous read, Download, Delete download) and the "Selected: N" header.
  - The top visible row stayed at the same position before and after the bar appeared (no jump).
  - Second selection updates the count to 2. Back exits selection and the list is unchanged.
  - Scrolled to the bottom with a selection active: the last row ("Chapter 0 - Prologue") is fully visible above the bar.
- Older chapter read: Chapter 10 of Overgeared (not the newest) draws pages in the reader. Full-screen hint "Got it" handled.
- Library genre filter:
  - Library options sheet opens on the Filter tab with the genre checkboxes (Action, Adventure, Comedy, Fantasy, Game, Murim, System) after titles were opened.
  - Action alone: Overgeared shown. Action + Game: only Overgeared (all ticked genres must match). Murim alone: only Nano Machine. Murim + Game: "Nothing matches" empty state. Clearing the filters restores both titles.
- Downloads: empty state "No downloads yet". After downloading one chapter the entry shows "1 ch. 19 MB".
- Send to nearby device: Select all, then Send shows "Waiting for the other phone" with a QR code, the instruction text and the manual-address fallback. The nearby-devices permission prompt appears first; the screen works after "Don't allow" (QR still shown).
- Receive from nearby device: permission prompt (denied, screen still usable) -> "Scan QR code" -> rationale dialog "Camera access" with Cancel / Continue -> system camera prompt -> "Don't allow" -> inline message "Camera access was denied. Allow it in the app settings, or type the address instead." Address field and Connect remain. No crash.
- Settings: root list opens; Appearance, Library and updates, and Sources and search sub-pages open and show their content. Sources screen (from Sources and search) opens and lists the built-in sources; MangaBuff shows the expected region block message. No sign-in performed.
- Dark and light (theme set in Settings > Appearance, plus system night mode toggle): Home, Library, chapter list render with readable text in both. Light chapter list, Library and Home read well. Dark Library and chapter list fine.
- Font scale 2.0: Home, Library, Chapter list, Sources and the reader menu open with no clipped controls. Top bars grow, bottom nav labels fit (no ellipsis needed on the nav bar at this scale). Font scale restored to 1.0.
- Rotation: landscape with a chapter selection active keeps "Selected: 1" and the selection bar; rotation back to portrait is clean. No crash.
- Logcat: no "FATAL EXCEPTION" at any point. AndroidRuntime entries are only from the test harness (monkey/uiautomator). The only Lume-related error-level lines are system-side (AppOps ACCESS_LOCAL_NETWORK for the nearby feature, WindowOrganizer task notices). No Room or migration errors.

## Problems found

No serious problems found.

Minor:

1. Long title wraps mid-word at font scale 2.0. "Overgeared" breaks as "Overgeare / d" in the Library cover caption and in the Continue reading card on Home.
   Steps: Settings > font size 2.0 (`settings put system font_scale 2.0`), open Library or Home. Screenshots: 52-font2-library.png and 57-font2-home-now.png (in the gate folder).

2. Dark-mode Home showed the text "e" inside the Quick search field in one screenshot (38-dark-home.png). It did not appear in later screens (light Home shows the placeholder "Quick search"). Cause not identified; not reproduced.

Notes (not defects):

- About screen on this debug build shows "Version 0.9.12 (44)". The version bump is part of the release step, so this is expected for a pre-release debug build.
- Genre filter depends on genres having been filled: a title added but never opened has no genres and cannot match a genre filter. Only the open-the-title path was exercised. Worth confirming that this is the intended behaviour (code reading, not run).
