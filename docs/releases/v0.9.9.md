# Lume v0.9.9

MangaDex works again, errors can be read in full, and reading statistics count only what you read in Lume.

## Fixed

- **MangaDex.** MangaDex started sending apps that look like a browser to a bot check, so the source failed with "Unexpected JSON token at offset 11". Lume now names itself to MangaDex, as its API asks, and the catalogue, titles, chapters and covers load again.
- **Reading statistics.** Chapters marked read by an import (MangaLib bookmarks, backups), sync, a tracker or "mark as read" no longer count. The chapter numbers per month and per title now include only chapters you opened and read in Lume, like the time and the pages already did. Nothing is deleted: the read marks stay as they were.

## New

- **Error log.** Errors of sources are shown in one line on the Sources screen, often cut off. The new **Error log** keeps the last 200 errors with their full text, the source and the time. Tap an entry for the technical details; copy one entry or all of them, share them, or clear the log. Open it from the warning icon at the top of **Sources** (red when a source has a recent error) or from **About → Error log**.

## Updating

Install it over v0.9.8 as usual. Your library, progress, bookmarks and downloads are kept. There are no database changes.

## Privacy

The error log stays in the app's private storage on your phone and is never sent anywhere. It leaves the phone only if you copy or share it yourself. MangaDex now sees the app name and version (`Lume/0.9.9`) instead of a browser name.

## For developers

- `data/network/Interceptors.kt`: `AppUserAgentInterceptor`, a network interceptor that sets `User-Agent: Lume/<version>` for `mangadex.org` and `mangadex.network` hosts. Being a network interceptor, it also overrides the image loader's User-Agent and applies to every redirect hop.
- `LibraryDao.observeChapterReadTimes` returns only read marks with a matching `reading_sessions` row (same source, title and chapter). No schema change.
- `data/ErrorLog.kt`: newest-first list of `ErrorEntry` (time, where, message, stack trace up to 6,000 characters), at most 200, saved as JSON in the app's files folder (read off the main thread at start). `SourceHealth` reports every failure to it through `onFailure`; `SourceRegistry` names the source. The screen is `ui/screens/ErrorLogScreen.kt` (route `error-log`).
- Tests: `ErrorLogTest` (order and cap, full message and stack trace, file loading, MangaDex host matching).
