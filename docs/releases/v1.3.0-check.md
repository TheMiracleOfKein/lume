## Possible bug spots (from reading the code)

1. `NovelPagedText.kt`, the `LaunchedEffect(session, settings, textWidth, pageHeightPx)`: the `snapshotFlow { pagerState.currentPage }` collector calls `vm.onPosition` without checking `restored`. When the page count changes on relayout, `currentPage` can be clamped and save a stale anchor. This matches the rotation drift below.
2. Pages are laid out with `pageTop`/`pageBottom` taken from the bars-hidden insets (`statusBarsIgnoringVisibility` / `navigationBarsIgnoringVisibility`). Showing the bars overlays them on the text rather than reflowing it (confirmed at the bottom, see failure 2).
3. `NovelReaderContent`: `rememberLazyListState` and the scroll restore sit after the early `return` for `vm.settings.paged`, so toggling the mode changes the composition structure mid-read. Worth checking for lost scroll state when toggling back.
4. `pageOf` returns page 0 when no page shows the anchor. A saved anchor for a block that no longer exists (chapter list changed) would jump to the start of the book, not the chapter.
5. Empty or single-row chapters: `paginate` returns an empty list for no rows. `pagerState` gets a page count of 0 and `turn(...)` is called on taps. Not reached in this run (no empty chapter available).
6. Chapter end: the pager keeps all chapters in one list. The next chapter's `Header` row starts a new page (`startsChapter`); the title page was not captured in screenshots (see not checked).
7. `PagedRow.Picture` is drawn with `fillMaxSize` inside a padded `Column`. A picture taller than a page is only tested through unit tests here, not on a device.
8. `NovelPages.kt` `paginate`: a line taller than a whole page is placed alone on a page (`end = line + 1`), so a very large font with a long line should still advance; not reached.
9. Catalogue empty state: when a source fails, the Catalog shows an empty list with no error text (only the Sources screen shows the failure).

## Failures and findings

### 1. Reading position drifts on rotation (and on reopen) — FIXED (see re-check below)

Not a crash, but the position was not kept, which step 7 requires. Severity is for the release owner to decide; it was a regression in the new paged reader, so it was listed first.

- Steps: open a chapter in the paged reader, turn to about 32%, rotate to landscape, back to portrait, read the percent on the bottom bar each time.
- Observed: 32% → 29% (landscape) → 23% (portrait) → 14% after a second landscape/portrait pair. Exit at 14%; reopening gave 12%.
- Likely spot: the currentPage collector in `NovelPagedText.kt` saves anchors during relayout without the `restored` guard (bug spot 1).

### 2. Paged text under the bars (layout) — minor to moderate

- Steps: paged mode on, tap the centre to show the bars, look at the bottom line of the page.
- Observed: the last line ("of the market, drowning out the …") is cut at the descenders by the progress bar; bars hidden the same page is clean.
- Not confirmed: the first line under the top app bar when the bars are shown (inferred from bug spot 2; it was not captured as a clear screenshot).

### 3. Empty Catalog on a failed source gives no message — minor

- Steps: ranobe build or full build with RanobeLib selected while it is unreachable. Catalog > Popular shows a spinner, then an empty list with no text. The Sources screen does show "Failed 1 minute ago: timeout".
- Suggest an error or retry line in the Catalog empty state.

### 4. Import: one file tap did not import; imported book is not in Library — minor

- Steps: Settings > Library and updates > Import books…, pick the file in the Downloads picker with a single tap. Lume returns to Settings; the book is not imported. Long-press the file, then Select, imports it.
- After import the book appears only under Local books (Catalog), not in Library ("Your library is empty"). Possibly intended; worth a look.

### 5. Title row under the app bar at the start of a book (scroll mode, bars shown) — cosmetic

- Steps: ranobe build, open the imported book in scroll mode; the large title line sits partly under the top bar at the first frame. Not re-checked after the bars were hidden.

## Environment notes

- The first `adb install` failed because Git Bash paths (`/d/…`) are not valid for the Windows adb binary; `cygpath -w` on the APK path fixed it.
- The sign-in-free RanobeLib path could not be used; all reading used the local TXT.
- Two early Back presses left Lume for the launcher, and later taps went to the system Settings app. This was a navigation error in the check, not an app bug; Lume was relaunched.
- The generated test text repeats some sentences in a paragraph (random sampling). That is the test file, not a Lume issue.
