# Lume v0.7.10

A safety release: downloads, backups, source packs, app updates and tracker sign-ins are harder to break.

## Fixed

- **Half-finished downloads no longer count as downloaded.** A chapter is now saved to a temporary folder and moved into place only when every page is there. Before, a download that failed partway (a lost connection, or the app closed during the download) could leave some pages behind, and on the next start Lume could list them as a complete chapter. Leftovers from interrupted downloads are cleaned up on start.
- **A paused or failed download can't show as running again.** A late progress update could put a stopped download back to "running", where it stayed stuck.
- **Restoring a backup is all or nothing.** If a backup file is damaged, the restore stops and your library stays as it was, instead of being half replaced. Settings from the file are applied only after the library part succeeded.
- **Very large or broken files are refused.** Backups, sync files and Mihon backups over 64 MB (unpacked) are refused instead of running the phone out of memory, and so are single pages over 48 MB.
- **Source packs can't take a built-in source's place.** A pack (imported, from a backup or from sync) with the id of a built-in source, such as `mangalib`, is refused, so it can never receive that source's sign-in. Pack ids may use only letters, digits, `-` and `_`.
- **Safer download folders.** Download folder names can no longer point outside their folder, and very long chapter names are shortened.
- **App updates are checked before installing.** Lume downloads updates only from its own GitHub releases, and refuses a file that is cut short or doesn't match the release checksum. A final version now counts as newer than its own pre-release (1.0.0 after 1.0.0-rc1).
- **Trackers stay signed in.** When several requests found an expired MyAnimeList, Kitsu or Shikimori token at the same time, each tried to renew it and the later ones could sign you out. Now one renews it and the rest use the new token. A server error while renewing no longer signs you out either; only a refused renewal does.
- **App lock hides content from screen readers.** While the lock screen is shown, accessibility services can't read the library behind it.
- **The library check stops when it is cancelled** instead of carrying on through every title.

## Updating

Install it over v0.7.9 as usual. Your library, progress, bookmarks and downloads are kept. No database changes.

If you imported a source pack whose id has dots or other characters besides letters, digits, `-` and `_`, it no longer loads; import it again under a plain id. The packs in Lume's own pack list are not affected.

## For developers

- `DownloadStore`: pages go to `<chapter>.lume-part`, renamed to the chapter folder on success; any failure (not only cancellation) removes it; `recoverFromDisk` deletes `.lume-part` folders. `abortPartial` keeps a finished copy (one with a download row). `safeFolderName` prefixes dot-only names and hashes names over 200 bytes.
- `DownloadQueue`: progress uses `updateRunningDownloadProgress` (`WHERE status = 'running'`).
- `BackupRepository.restorePayload`: database rows in `withTransaction`, settings after. `readCapped` (64 MB) for backup, gzip and sync reads; `AppHttp.getBytes` caps at 48 MB.
- `SourceRegistry`: `importJson`, `load`, backup restore and sync skip bundled ids and ids failing `isValidPackId`.
- `AppUpdater`: `isTrustedApkUrl`, size check, SHA-256 from the asset `digest`; `isNewer` orders pre-releases.
- MyAnimeList, Kitsu and Shikimori: refresh under a `Mutex`, reusing a token another call already renewed; sign-out only on 400/401. AniList token request built with `buildJsonObject`.
- New tests: `SafeFolderNameTest`, `PackIdTest`, `ReadCappedTest`, more `AppUpdaterTest`.
