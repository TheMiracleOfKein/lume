# v0.7.9 pre-release check

Build: debug APK from branch fix/no-predictive-back (HEAD 9c93bca), installed on emulator-5554 (API 37, 1080x2400) with `adb install -r`. Verified in the APK: `android:enableOnBackInvokedCallback="false"` and targetSdkVersion 37. Version name in the APK is 0.7.8 (this change has no version bump).

## Changed areas

- AndroidManifest.xml: `android:enableOnBackInvokedCallback="false"` on the application (was "true"). Goal: no predictive-back animation anywhere.

Crash grep: `adb logcat -d | grep "FATAL EXCEPTION"` printed nothing (count 0), re-checked after all steps.

Back-dispatch logcat (`grep -i "OnBackInvoked\|predictive" | head -20`): Lume's MainActivity callbacks report `mIsAnimationCallback=false` with `mType=TYPE_CALLBACK`, so the system did not start a predictive animation for Lume. The "OnBackInvokedCallback is not enabled for the application" warnings from WindowOnBackDispatcher are the expected effect of the opt-out. The only `mIsAnimationCallback=true` entries are from Chrome's first-run activity, not from Lume.

## Side effects during testing

- Reader taps moved the reader to chapter 146 (a "Previous chapter" tap); no data changed.
- A Chrome sign-in screen opened from a mis-tap; dismissed with back. No sign-in or password typed.
- Extra back presses left Lume for the launcher once, and once for Google search; Lume was relaunched both times.
- Added "SSS-Class Suicide Hunter" earlier, and "Chronicles of the Lazy Sovereign" to the library (bookmark tap), during the library tests.

## Result

PASS: places 1, 2, 3 (gesture), 4 (selection and search), 5, 6 (gesture), 7, and 8 (tab fade). The forward slide was not confirmed frame-by-frame. No crashes.

So far no place shows a predictive-back animation: every held-gesture frame is full size with at most the edge arrow. The change looks right. Still open before a release sign-off: the reader page drawing on an old chapter from a second source, a frame-level check of the forward slide, and the release APK smoke test.
