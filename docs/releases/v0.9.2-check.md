## Possible bug spots (from reading the code)

1. Cleartext: the platform now permits plain HTTP for every host. Only the OkHttp client's `CleartextGuardInterceptor` blocks plain HTTP to unknown hosts. Any request path that does not use that client (WebView, another HTTP client) is not guarded. Not reproduced.
2. Edit with an empty password keeps the saved sign-in ("Leave empty to keep the saved sign-in"). If the host (not just the path) is changed, the saved password may be sent to the new host. Only a path change was tested (check e).
3. Cookies: server origins never store cookies (`ServerCookieJar`), and other sources keep them. Cloudflare-protected sources depend on cookies. No Cloudflare source was tested on device.
4. `CatalogViewModel` refreshes sections after the first feed for every source. Observed a stale listing after switching servers (minor M1).
5. Progress write-back in `ReaderViewModel.reportToServer` only runs for engines that implement `ReadProgressSink`. MangaKatana progress still works (check g).

## Findings

### Serious

None confirmed (no crash, broken navigation, data loss, layout break or credential leak reproduced on device).

Potential, from code reading, not reproduced (for the user to decide):
- Bug spot 2: Edit server with an empty password and a changed host may send the saved password to the new host. Repro idea: Komga server, Edit, change the address to a different host (for example the same port on another address), leave the password empty, Save, then browse. Check which host receives the Authorization header.
- Bug spot 1: plain HTTP is permitted at platform level for every host. Confirm that no non-OkHttp path (WebView, image loader outside the client) can send an http:// request to an unknown host.

### Minor

- M1. Stale catalogue after switching server. Repro (observed once): Sources, select "Lume OPDS" (catalogue shows Lume Test One and Two), then select the unreachable "Lume Dead" server, then open Catalog without restarting. The catalogue still listed Lume Test One and Two with no section chips and no error. After an app restart it showed the expected error. Not confirmed on repeat.
- M2. Reader message. Scrolling to the bottom of Komga's Lume Test Two Chapter 1 showed the toast "This is the last chapter", and the reader was then in Chapter 2. The message is misleading while a next chapter exists. Repro: open Lume Test Two (Komga), Chapter 1, scroll to the end.
- M3. Komga Lume Test Two Chapter 2: repeated swipes stopped at page 3 of 4, so page 4 was not seen. Not determined whether this is a reader issue or a swipe issue on the emulator. Re-check on device.
- M4. Remove a server has no confirmation (one tap removes it). Behaviour note, not a crash.
- M5. Komga and Kavita covers look like solid colour blocks, the same colour as the first test page. Not confirmed whether these are the real cover images.
