## Changed areas
1. Encryption at rest: tracker tokens, site sign-ins, WebDAV password and sync passphrase are stored encrypted (Android Keystore). Plain values written by v0.9.10 must be encrypted on first start and keep working.
2. Long press on a "Continue reading" card (Home) or a History row opens "Remove from history?" with Remove / Cancel. Remove takes only that title out of Continue reading and History. Chapter read marks stay.

## Findings

1. Dialog title quoting (cosmetic). The English dialog wraps the title in curly quotes around the title's own quotes: `““"Aishiteru", Uso Dakedo.” leaves Continue reading…`. The Russian dialog wraps it the same way with guillemets. Readable, but a double-quote pair looks like a mistake. Suggest removing the outer quotes or the title's own quotes in the format string.
2. Saved position after Remove (needs a decision). The dialog says the saved position "is forgotten". After Remove, the chapter list of the removed title still shows "Chapter 1 : Story 1 · p. 2 / 51" (the page progress of an unfinished chapter). Read marks are kept, as required. Either the page progress is meant to survive (and the dialog wording should say only that the Continue reading entry is forgotten), or it should be cleared. Not a crash or data loss.
3. Sync status text. After the WebDAV save, Sync shows "Sync failed: no connection to the server". This is expected because the test server does not exist. Not a bug.
4. Unexpected Google sign-in screen (not from Lume). Once during this run, a Google Accounts "Sign in" screen appeared on top of the device. The system log shows it was started by Google Play services, not by Lume. I dismissed it without signing in. It did not recur. Not investigated further.

Not checked because the rules forbid signing in to real accounts, and the test values were not signed in. Only the sync secrets (WebDAV password and passphrase) were verified through the upgrade.

- Release build and R8 behaviour (debug builds only).
- Android-MCP driven walks (tools not available in this session; adb used throughout).
- Fresh-install behaviour (the uninstall step failed with an internal error, so the test used a data clear and an install over the existing app instead).
