# Lume v0.7.13

Chips and leftovers: genres you can tap, one-tap library filters, the bell for many titles at once, a Continue button on covers, a warning before adding a title twice, update checks that skip what you don't need, and a status line for broken sources.

## New

- **Tap a genre.** The genre chips on a title's page now open that source's catalogue filtered by the genre, using the site's own filter. When the site has no filter by that name, Lume searches for it instead.
- **Filter chips in the Library.** Unread, Downloaded, Started, Tracking and Completed sit as chips under the categories. A tap goes from off to "only these" to "hide these" and back. Turn the row off in the library options (Display) if you don't want it.
- **The bell for several titles.** Select titles in the Library and tap the bell: it turns on for the ones without it, or off when all of them have it. Up to 20 titles can have the bell; Lume says how many were left out.
- **Continue button on covers.** Turn on "Continue button on started titles" in the library options (Display): a play button on titles you've read opens the reader where you stopped.
- **"Already in the library?"** Adding a title whose name matches one in your library from another source asks first. "Link to it" adds this source to the title you have (its chapters fill gaps, and a chapter that fails loads from here); "Add anyway" adds a second entry.
- **Smarter update checks.** Settings → Library and updates can skip completed titles, titles you haven't started, and titles with unread chapters, and can make background checks wait for the charger. "Update now" still runs at once.
- **Source status.** The Sources screen shows when a source's last request failed, with the error, or that the site asks for its browser check. It clears as soon as the source answers again.
- **Readable release notes.** The update dialog shows headings, lists, bold text and links instead of raw Markdown.

## Updating

Install it over v0.7.12 as usual. Your library, progress, bookmarks and downloads are kept. The database doesn't change. The new update-check rules start off, so checks behave as before until you turn them on.

## For developers

- `FilterList.withGenre` matches a genre against check and tri-state filters (case and separators ignored); `Routes.browse(sourceId, genre)` and `CatalogViewModel.genreFeed`.
- `LibrarySettings.filterChips`, `continueButton` and `cycled()`; `LibraryViewModel.toggleBells` with `domain/BulkBell.planBulkBell`; `continuePoint` opens the reader through `openReader`.
- `sameNamed` in `TitleMatching` (by `normalName`); `TitleViewModel.duplicate` drives the dialog; "Link to it" uses `TitleSourceRepository.link`.
- `domain/UpdateRules` stored in four preferences; `LibraryUpdateWorker` filters its pool with library stats and the cached status; `schedule(chargingOnly)` sets `setRequiresCharging`.
- `data/source/SourceHealth` records each source's last failure in `DispatchingSource` (cancellation is ignored, a success clears it); `SourcesViewModel.problems`.
- `util/Markdown` parses headings, nested bullets and inline marks; `UpdateUi` renders them with `LinkAnnotation.Url`.
- New tests: `LibraryExtrasTest`, `SourceHealthTest`, `MarkdownTest`.
