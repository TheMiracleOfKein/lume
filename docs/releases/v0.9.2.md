# Lume v0.9.2

Read from your own server: OPDS catalogues, Komga and Kavita.

## New

- **Add server.** Sources → Add server. Pick OPDS, Komga or Kavita, enter the address and sign in with a user name and password or an API key. The server shows up as a source: browse, search, add titles to the library and read like any other source. Servers can be renamed, edited and removed.
- **Komga and Kavita.** Series, chapters, covers and pages come straight from the server. What you read is sent back, so the server knows where you stopped.
- **OPDS.** Any server that speaks OPDS 1.2 or 2.0 (Komga, Kavita, Calibre-Web and others). The catalogue's sections become the chips at the top. Pages are streamed when the server supports it; otherwise the chapter file (CBZ, CBR, CB7 or PDF) is downloaded and opened.
- **Home servers over http.** Plain `http://` works for servers you add, with a warning that the connection isn't encrypted. On Android 17 Lume asks for access to your local network when you add a server there. Every other site still needs `https://`.
- **Sign-ins stay safe.** They are encrypted on the phone with a key from the Android Keystore and sent only to the server they belong to. If you change a server's address to another host, port or from https to http, Lume asks for the password or key again instead of sending the saved one.
- **Clear errors.** "Could not connect" and "rejected the sign-in" messages instead of technical ones.

## Fixed

- The reader could say "This is the last chapter" at the end of a chapter that wasn't the last.

## Known issues

- In one test chapter on Komga the reader stopped at page 3 of 4 at the end of the last chapter, so the chapter wasn't marked read. If it happens to you, open the chapter list and mark it read there.
- Backups and sync carry your servers but not their sign-ins: after a restore, edit each server and sign in again.

## Updating

Install it over v0.9.1 as usual. Your library, progress, bookmarks and downloads are kept. The database doesn't change.

## For developers

- `data/server`: `ServerCredentialStore` (AES-GCM, Keystore key, own DataStore file, excluded from backups) behind a `CredentialCipher` interface; `ServerAuth` (manifests `server-<uuid>`, same-origin rules, credential merge); `ServerAuthInterceptor` (network interceptor: Basic, `X-API-Key` or Bearer on matching scheme, host and port); `ServerCookieJar` (no cookies for servers); `CleartextGuardInterceptor` and `GuardedWebViewClient`.
- `data/source`: `KomgaEngine` (`/api/v1`, `PATCH read-progress`), `KavitaEngine` (JWT from `Plugin/authenticate`, refreshed on 401; the API key is filled into image URLs only at request time), `OpdsEngine` with `OpdsFeed` (Atom through jsoup, OPDS 2 through kotlinx-serialization, OPDS-PSE).
- `ReadProgressSink`, called from `ReaderViewModel` (2 s debounce, finished chapters at once, nothing in incognito). `SourceSetting.Text` for text and password settings. `AppHttp.sendJson` for JSON writes.
- Network security config allows cleartext; the guard interceptor and the WebView client limit it to added servers. `ACCESS_LOCAL_NETWORK` is declared and requested on SDK 37+.
- New tests: Komga, Kavita and OPDS parsers (including saved feeds from real Komga and Kavita servers), interceptors, cookie jar, same-origin rules, credential store with a fake cipher, chapter neighbours.
- Device check: [v0.9.2-check.md](v0.9.2-check.md), against local Komga and Kavita (0.9.1.4) servers in Docker.
