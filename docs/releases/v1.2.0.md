# Lume v1.2.0

Ranobe mode gets its first online source, RanobeLib, and novel chapters can be downloaded to read offline. The mode is no longer marked as a preview.

## New

- **RanobeLib.** A new source in Ranobe mode, with the same features as MangaLib in Manga mode:
  - Catalog, search, the site's genres, tags and other filters, and title details;
  - chapters with their translation teams; paid early-access chapters aren't listed until they open for everyone;
  - ranobe, light novels and web novels all open in the text reader, pictures included;
  - sign in from Sources (the key icon), then **⋮ → Import bookmarks** brings your RanobeLib bookmarks into the Ranobe library, folders as categories;
  - RanobeLib links from the browser open the title in Lume.
- **Novel downloads.** Novel chapters download like manga chapters: from the chapter list, with **Download new chapters** for titles with the bell, and with **Delete after reading**. A chapter is saved as its text with its pictures, in the download storage you chose, and the Downloads screen marks it **Text**. A downloaded chapter opens without the internet. If a picture can't be downloaded, the text is still saved and that picture loads from the site when you're online.
- **Ranobe is out of preview.** The mode switcher no longer shows the Preview badge.

Only the full build has the Ranobe mode; the manga build is unchanged.

## Fixed

- Bookmarks imported from a Lib site go into the library of that site's mode. Before, every imported title went into the Manga library; MangaLib, YaoiLib and HentaiLib imports are unchanged.

## Not yet

- Sending novel downloads to a nearby phone (manga only for now), novel lists on trackers, English novel sites, and a page-by-page mode in the text reader.

## Updating

Install it over v1.1.2 as usual. Your library, progress, bookmarks, downloads and sign-ins are kept. No database change.

## For developers

- The MangaLib-family API client is shared: `LibSocialBase` in `core/data` holds the catalogue, filters, details, chapters with teams, the paid-chapter skip, bookmarks and links. `LibSocialEngine` (comics) keeps only the pages and image servers; `RanobeLibEngine` (`ranobelib`, in `:feature:novel`) adds chapter text. `SourceEngines.isLib` covers the family for the request limit and the Sources sign-in. New `engineConfig.webPath` (`manga` / `book`).
- `LibChapterText` turns a chapter answer into HTML: the rich-text document (`type: doc`, text nodes with marks, headings, lists, images by attachment) or the HTML string, whose own `<img>` links are kept (attachment URLs sometimes answer 500).
- Text chapter downloads: `chapter.html` plus `img-0000.<ext>`… flat in the chapter folder (`TextChapterFiles`), paths in the row are the HTML then the pictures, `pageCount` counts the pictures. `DownloadStore.localText` reads one back; recovery from disk and from a picked folder knows the layout. `DownloadQueue.canDownload` allows novels, not the local sources.
- `LibBookmarkImport` writes `mediaKind` from the source on new library entries and continue points.
- Unit tests run on OkHttp's JVM build (the Android build needs Android assets for its public-suffix list); the weekly live source check, which failed on that since early November, works again, and checks RanobeLib from the novel module.
- New JVM tests for `LibChapterText`, the RanobeLib engine (from real chapter answers), `TextChapterFiles`, and novel downloads through the real `DownloadStore`. The device check is in [v1.2.0-check.md](v1.2.0-check.md).
