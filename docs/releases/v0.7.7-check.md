## Possible bug spots (from reading the diff)

1. `BackGestureCard`: the `byGesture` flag is a plain `booleanArray` in `remember`, not state. A leave that starts under a gesture keeps its corners after the finger lifts. If a gesture is cancelled, `leaving` goes false and the corners should animate back to 0. Only reading and the adb tests back this up; it needs a real finger drag to confirm.
2. `popping` map in AppShell: a cancelled pop leaves the entry in the map until its DisposableEffect fires or a forward exit removes it. The `popped` flag could then be stale on a later exit. Only a forward exit (`exitTransition`) clears it, so a pop that is cancelled and then followed by a forward navigation from that screen should be checked.
3. Corner radius: `rememberDisplayCornerRadius` caches the value in `remember(view, density)`. If `rootWindowInsets` is null on first composition, the 28 dp fallback sticks. Rotation was tested only for a crash, not for the radius.
4. Reader leaving: the card shows a shadow and rounded corners over the reader's black pages. Not visually checked (the pages did not render).
5. Forward navigation and tab switches: `leaving = exiting && !isTab` and `popped` only apply to pops, so these should stay square. Checked for the Library tab (see below).
6. Login screen: the hint text is now a Column child above a `weight(1f)` WebView. Long Russian text may wrap to more lines (about 3 lines in English on this device). Not checked in Russian.
7. Cosmetic: indentation in `SourceLoginActivity` (the Column body is not re-indented), and `AppShell.kt` imports are not sorted. These do not affect behaviour.
