# Lume v1.0.0

The first stable release, and the base for more kinds of reading. Lume now has reading modes: Manga today, Ranobe (light novels) as a preview, with more to come. From this release there are two builds, so you can pick one with every mode or a smaller one with manga only.

## New

- **Reading modes.** Long-press the logo in the middle of the bottom bar (or the logo in the side rail on a tablet) to switch between Manga and Ranobe. The main menu has a "Mode" entry too. The library, history, sources, downloads and reading statistics show only the current mode; your manga stays exactly where it was.
- **Ranobe preview.** The Ranobe mode is in place, but it has no sources or text reader yet, so its screens say that ranobe sources are coming. RanobeLib, English novel sites and local EPUB/TXT files are planned next.
- **Two builds.**
  - `lume-v1.0.0-full.apk`: every reading mode.
  - `lume-v1.0.0-manga.apk`: manga only, no mode switcher; it looks and works like before.

  Both use the same app ID and signature, so you can install one over the other and keep your data. The in-app updater stays on the build you installed.

## Updating

Install it over v0.9.16 as usual. Your library, progress, bookmarks, downloads and sign-ins are kept.

- The in-app updater of v0.9.x takes the first APK of a release, which is the full build. If you want the manga-only build, download `lume-v1.0.0-manga.apk` from the release page and install it over the top.
- **Database change:** an additive migration (version 16) marks every existing title and reading position as manga. Backups from older versions still load (as manga), and backups made by 1.0 load in both builds; a build without a mode keeps that mode's titles and just hides them.

## For developers

- The single `:app` module is split into `:core:model`, `:core:common`, `:core:data`, `:core:ui`, `:feature:comics` and `:feature:novel`, with `:app` only assembling them. Package names are unchanged. See [ARCHITECTURE.md](../ARCHITECTURE.md).
- `MediaKind` (`Comics`, `Novel`, `Video`) comes from the source manifest's `mediaKind`. `getPages()` moved to a `ComicSource` subinterface; each feature module provides a `ContentModule` (engines, screens, label, icon) and `SourceEngines` builds engines from the installed modules instead of a fixed `when`.
- Product flavors `full` and `manga` (dimension `modes`), each with its own `InstalledModules.kt`. Tasks are per flavor (`assembleFullRelease`, `testMangaDebugUnitTest`, …). The release workflow publishes both APKs, each with a `.sha256`; `AppUpdater.pickApk` downloads the asset named for `BuildConfig.FLAVOR`.
- `AppPreferences.activeMode` drives the shared screens; trackers take a `kind` parameter (only comics endpoints for now).
- The version now lives in `gradle.properties` (`lume.versionCode`, `lume.versionName`).
- Checked: unit tests, lint and screenshot tests for both flavors; the pre-release device check is in [v1.0.0-check.md](checks/v1.0.0-check.md).
