# Lume v0.9.16

A fix release: the filter sheet no longer moves up and down without end after a hard swipe.

## Fixed

- **Filter sheet after a hard swipe.** With a long filter list open (for example all genres), a hard swipe through the list could leave the sheet jumping up and down without stopping. The sheet now settles in place.

## Updating

Install it over v0.9.15 as usual. Your library, progress, bookmarks, downloads and sign-ins are kept. No database change.

## For developers

- Cause: the leftover fling velocity from the list goes to the `ModalBottomSheet` (Material3 1.4), which settles to Expanded with a spring that overshoots past the anchor into the status bar. There the sheet's default `contentWindowInsets` (`safeDrawing` top minus the consumed offset) add top padding, the sheet grows, the Expanded anchor moves, and the settle starts again. The v0.9.15 height cap only kept the resting position below the status bar.
- Fix: both filter sheets (catalogue and search) pass `contentWindowInsets = { FilterSheetInsets }`, the bottom `safeDrawing` insets only, so the sheet's height no longer depends on its position.
- Checked on the emulator (debug build): three hard flings over the expanded genre list. Before the fix the sheet moved without end; after it, it stays put. A hard downward fling still closes it. No release smoke test, at the owner's request.
