## Changed areas

- Royal Road and Scribble Hub catalogue filters (`feature/novel/.../RoyalRoadEngine.kt`, `ScribbleHubEngine.kt`, filter sheets).
- Readable error text (`core/data/.../ErrorMessages.kt`, `Throwable.userMessage()`), used by the novel reader and the catalogue.
- Per-title text reader settings: "Save for this title" (`feature/novel/.../NovelReaderViewModel.kt`, `NovelReaderSettingsSheet.kt`), Room `TitlePrefsEntity`.
- Novel tracker link sheet and novel tracker list (`core/data/.../tracker/*`).
- Regression areas: manga reader settings, title details, Library, Updates, Trackers settings.

## Possible bug spots (from reading the code)

1. `NovelReaderViewModel.initSettings()` runs in a separate coroutine after the reader opens. A settings edit made before it returns is overwritten by the stored title overrides. Not reached in this run (the sheet was opened after load).
2. `resetSettings()` clears the title overrides and writes the global defaults. Verified on device, see below.
3. `updateSettings(commit = true)` with "Save for this title" on copies only size, theme and page mode back to the global settings (`keepingGlobalTitleFields`). Other fields (line spacing, margins, font, justify) still go to the global default. This matches the intent in the code, but it means those fields are shared across titles even with the switch on. Not visible in the walk; worth a decision.
4. `ErrorMessages.of()` returns the generic text when a message looks like an obfuscated name (1 to 4 characters). Not exercised beyond the offline case.
5. Royal Road and Scribble Hub both need a Cloudflare check on a fresh session. This is a site behaviour, not a bug (see findings).

## Failures and findings

No serious findings (crash, broken navigation, data loss, layout break, feature not working). Minor items:

### 1. No Trackers entry in Ranobe-mode Settings (minor) — FIXED (see Re-check)

- Steps: switch to Ranobe mode (Menu > Mode > Ranobe), open Menu > Settings, look at the list or search "tracker".
- Observed: the rows are Appearance, Reader, Library and updates, Sources and search, Sync, Backup and restore, Privacy, Network and storage, About. The search for "tracker" only returns "Clear cookies". Manga-mode Settings has a Trackers row (Accounts).
- Expected per the v1.5.0 notes: Settings > Trackers reachable in both modes. If the Ranobe tracker entry is intentionally hidden, the novel tracker links are reachable from the title sheet only.

### 2. Offline "Next chapter" in the novel reader gives no message (minor)

- Steps: Scribble Hub title, Read, then turn mobile data off, tap "Next chapter" (and again).
- Observed: the reader stays on Prologue and no error text appears, unlike the catalogue.
- Expected: the readable sentence from `ErrorMessages`, as in the catalogue.

### 3. Offline search can end with an empty list and no text (minor, intermittent)

- Steps: Scribble Hub, mobile data off, search "zebra" in the catalogue.
- Observed: a spinner for about 40 s, then an empty list with no message. A later offline request (sort changed) showed "Can't reach the site..." with Retry. Not reproduced on the search path a second time with certainty, because a stale message may have been on screen.

### 4. Manga "Save for this title" is a button and its effect is not confirmed (minor)

- Steps: manga title, Chapter 2, Settings, scroll to "Save for this title", tap.
- Observed: a plain button (the novel sheet uses a switch). No confirmation text or state change was visible afterwards.
- Expected: either a switch like the novel sheet, or visible feedback that the settings were saved for the title. Behaviour after reopening was not checked.

### 5. Cloudflare checks on Royal Road and Scribble Hub (site behaviour, not a bug)

- A fresh session shows the Cloudflare page. The Turnstile widget needed the "Verify you are human" checkbox once, then Continue; afterwards the lists loaded. This matches the known site issue.
