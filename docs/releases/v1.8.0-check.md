# Lume v1.8.0: pre-release device check (story lookup, codex, recap)

## Summary

- **Final result: no crash, no broken navigation, no data loss, no layout break.** Serious problems: none.
- Covered: long-press lookup in scroll and paged mode (first appearance, mentions, coverage line, snippet expand, term edit, save to codex), Codex screen (list, search, edit, delete, empty state, back to reader), rotation with the lookup sheet open, Settings → Reader (Ranobe) story index switch, recap choice, index size line and Clear story index, "Previously…" recap on reopen (forced with the emulator clock), in-app backup creation.
- Non-serious findings from the first run are all fixed and re-checked (see "Re-check"). One design note stays open (the recap includes the paragraph at the spot).
- Not covered: saving the backup to a file, restore, incognito, translated text, "Show original", the lookup overflow menu (All entries, Rebuild for this title). See "Not checked".

## Setup

- Build: debug, full flavour (`app-full-debug.apk`), uninstalled and reinstalled, logcat cleared. The APK file timestamp is from the morning of the check, so it may predate the latest commit; rebuild before the release gate if the code changed since.
- Device: emulator Lume_Light (Android 14 / API 34, 720x1600), Wi-Fi disabled, mobile data used.
- Source and title: Royal Road (English), "The Runesmith" (Ongoing, 732 chapters). Reader ran in Ranobe mode.
- Royal Road shows a Cloudflare check on the first load and on some chapter loads on this emulator. Tapping the checkbox and Continue got through each time. This is the environment, not the app.
- Clock: the emulator date was moved forward two and then eight days for the recap check and restored to host time afterwards (Settings → Reader was left at "After 6 hours" and Ranobe mode, source Royal Road; the emulator is read-only, so these reset on exit).

## Possible bug spots from reading the code (not reproduced)

- `NovelReaderViewModel.search()`: the coroutine can reassign `lookupState` after `dismissLookup()` if the cancel lands after the last suspension point, which would reopen the sheet. Not seen in the walk.
- `NovelReaderViewModel.saveCodex()`: the search term after saving is chosen by a `takeIf` on the existing name; with a rename of an entry the sheet can search the old term. Not checked.
- `NovelReaderViewModel.lookup()`: a null `offset` or a block without text falls back to `onNoTerm`. Not tested (long-press in margins did nothing, which is the same path).
- Translated text: the lookup searches `originalText()` for both the shown and original text; "Show original" and translated paragraphs were not checked (no translation add-on in this walk).
- Incognito: `buildRecap` returns early for incognito; the story index writes were not checked for incognito.
