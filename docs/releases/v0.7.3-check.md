# Lume v0.7.3 pre-release check

Branch: fix/lib-bookmark-import (commit 4642ea3). Build: app/build/outputs/apk/debug/app-debug.apk, installed on emulator-5554 over the previous debug install (uninstall failed with DELETE_FAILED_INTERNAL_ERROR, so app data was kept).

## Changed areas (v0.7.2..HEAD)

- `SourceRegistry.kt`: `DispatchingSource` and `ImageHostTrackingSource` implement `WrappingSource`; new `engineById()` and `CatalogSource.unwrapped()`. `sourceById()` is unchanged. Every screen goes through the wrappers.
- `LibBookmarkImport.kt`: uses `engineById` so the Lib engine is reached through the wrapper.
- `LibSocialEngine.fetchBookmarks()` and `LibBookmarks.kt`: one paged pass with `status=0`, falling back to per-folder reads. `withDefaultLibFolders` names the built-in statuses.
- `SourcesScreen.kt`: the "Import bookmarks" item is passed only when a Lib token exists (line 165).

## Possible bug spots (from reading the code)

1. `LibBookmarks.kt` `parseLibBookmarksPage`: `meta?.get("next_page_url").bool()` reads a JSON boolean. The site sends `"next_page_url": true`, so this branch is live (corrected from the first draft, which assumed a URL string). Minor: no paging change needed; the fallbacks cover responses without it.
2. `LibSocialEngine.fetchBookmarks()`: `readStatus` is wrapped in `runCatching`. If page N fails, every page already read is discarded and the per-folder fallback runs. Duplicates are removed by `distinctBy`, but the work is repeated. Minor.
3. `withDefaultLibFolders`: the built-in status names are hard-coded in Russian. Minor, and only relevant when the site's folder call fails.
4. The import action is hidden when signed out, so a signed-out user never sees the sign-in-needed path. Expected by design, but the user gets no hint that the feature exists. Minor.
