# Lume v0.9.11

Your sign-ins are now stored encrypted on the phone, each release has a checksum file next to the APK, and you can take a single title out of Continue reading and the history.

## New

- **Encrypted sign-ins.** Tracker sign-ins (AniList, Shikimori, MyAnimeList, Kitsu, MangaUpdates), sign-ins to MangaLib-family sites, and the WebDAV password and passphrase for sync are now encrypted with a key from Android's Keystore. The key never leaves the phone's secure storage, so the saved values can't be read from a copy of the app's files. Sign-ins saved by an older version are encrypted the first time v0.9.11 starts; you don't have to sign in again. Server sign-ins (Komga, Kavita, OPDS) were already stored this way.
- **Remove one title from the history.** Long-press a card under **Continue reading** on Home, or a title in **History**, and choose **Remove**. Only that title goes away. Its chapters keep their read marks and the page you stopped at in each. **Clear** still removes everything. With TalkBack, "Remove from history" is in the actions menu.
- **Checksum file.** Each release now has `lume-vX.Y.Z.apk.sha256` next to the APK, so Obtainium and other installers (or you, with `sha256sum -c`) can check that the download is complete and unchanged.

## Updating

Install it over v0.9.10 as usual. Your library, progress, bookmarks, downloads and sign-ins are kept. There are no database changes. Backups from every earlier version still restore.

If you move to a new phone with Android's device-to-device transfer, the Keystore key stays on the old phone. Tracker and site sign-ins then have to be done again on the new one, as server sign-ins already did.

## Privacy

Encrypted values stay in the app's private storage and, as before, are left out of Android's cloud backup and out of Lume's own backups and sync. Cookies of sites you signed into through the built-in browser are kept by Android's WebView, which Lume can't encrypt. They are also left out of cloud backups.

## For developers

- `data/security/SecretSealer`: AES-256-GCM through `KeystoreCredentialCipher` with the key `lume_secrets`. Sealed values start with `lume-sealed:1:` and are Base64 `iv || ciphertext`. Values without the prefix are read as plain text. A value that can't be decrypted reads as null (signed out), and if the Keystore can't encrypt, the plain value is kept so the sign-in still works.
- `AppPreferences`: the secret keys of `lume_private` (names with `token`, `secret`, `password`, `verifier` or `passphrase`, and every `tracker_*` value) are sealed when written and once on start (`sealPrivateValues`). Client ids, user ids, the backup folder and the sync address stay readable.
- `LibAuthStore`: tokens are sealed when saved; `sealStored()` runs on start from `AppContainer`.
- History: `HistoryViewModel.remove` and Home call `LibraryDao.clearProgress(sourceId, titleId)`. `RemoveFromHistoryDialog` is shared. `TitleListRow` takes an `onLongClickLabel`.
- `docs/RELEASING.md`: a pushed `v*` tag publishes the release through the workflow, with the APK and its `.sha256`. A local release attaches the checksum too.
- Tests: `SecretSealerTest`, `LibAuthStoreTest`, and `PrivatePreferencesTest` (plain values sealed on start).
