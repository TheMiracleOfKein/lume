# Lume v1.7.0: pre-release device check (chapter translation)

## Summary

- **Final result: 11 of 11 walk checks pass, no crash, no broken navigation, no data loss, no layout break.** Serious problems: none.
- Covered: translate sheet (engine choice, "Read in English", DeepL key hint), Google Translate chapter translation, long-press original (scroll and page mode), glossary screen (add, edit, search, paste, copy all, delete, back to reader), page-by-page mode, rotation, reopening a translated chapter, switching translation off, the add-on's own launcher screen and "Open Lume", and the app in Russian (sheet, glossary, reader).
- Not covered: the offline (on-device) translation, because no Russian to English offline model is available in the add-on for this title, and real arm64 speed. See "Not checked".
- Minor observations (not failures) are listed at the end.

## Setup

- Build: debug, `app/build/outputs/apk/full/debug/app-full-debug.apk` (flavour full) and `translate-addon/build/outputs/apk/debug/translate-addon-debug.apk`. Both uninstalled and reinstalled, logcat cleared.
- Device: emulator Lume_Light (Android 14 / API 34, x86_64, 720x1600), Wi-Fi disabled as instructed, mobile data used.
- Source and title: RanobeLib, mode Ranobe, title "Повелитель тайн" (Lord of Mysteries), Vol. 1 Ch. 1 "Багровый" (1436 chapters in the list).
- The app started in Manga mode and was switched to Ranobe through Menu > Mode.
- Speech and audio were not checked (emulator runs without audio).

## Failures

None.

## Minor observations (not failures)

1. **Glossary search with no match** (check 4): the list empties, but the header count still reads "2 terms" and no "no results" text is shown. Cosmetic.
2. **Chapter opening** (check 7): on reopening, the reader showed the header and progress bar, but no text for a few seconds; the translated text then appeared. Not an error, but the first frame is blank.
3. **Long-press between paragraphs** (checks 3 and 5): a long press in the gap between two paragraphs opened the nearest paragraph in one case and did nothing in another (page mode). Pressing on the text itself always worked.
4. **Logcat warning at first launch of the add-on**: `W PackageManager: Failure retrieving resources for com.lume.translate` appeared once; no visible effect.
5. **Glossary editing note**: the edit test was typed without a space, so the saved target is "KleinM". This was a test input mistake, not an app bug; the edit and save path works.
6. **Read in English row when no engine is picked**: the row is not flagged as disabled for accessibility; only the hint text shows it is unavailable.

## Not checked

- **On-device (offline) translation**: the add-on has no Russian to English pack for this title, so "On the phone" stays disabled. Pack download, the add-on translating a chapter, and the add-on's "Open Lume" smoke test on a Royal Road chapter (blocked by a Cloudflare check on this emulator) were not run.
- **Real arm64 device speed** and translation time per chapter on hardware.
- **Audio**: read aloud with translation, speed and voice: the emulator runs without audio.
- **Engine switch while a chapter is translating** (switch from Google to DeepL with a job running), and language change (EN/RU) in the middle of a translation.
- **Real DeepL key**: not entered, by design of the walk.
- **Glossary paste formats** beyond `=` and `->` (for example tab-separated columns).
- **Copy all**: no crash, but the clipboard contents were not read back.
- **Bold text** in the translated output: not seen in the sampled passages.
- **Rotation in page mode** and **back navigation from the glossary in the middle of a translation**.
- **Backup, sync and the database migration** (v17 to v18): covered by unit tests and CI, not by this walk.
