# v0.9.6 pre-release device check

Date: 2026-11-11. Build: debug APK built from HEAD of branch feat/library-sources-stats with `./gradlew.bat :app:assembleDebug` (succeeded, all tasks up to date). The debug build reports versionName 0.9.5 because the version bump is a release step.

`adb uninstall` failed with DELETE_FAILED_INTERNAL_ERROR, so the APK was installed with `adb install -r` over the existing install and app data was kept (the library already held titles from earlier runs).

Device: emulator-5554 (Pixel 6a image, 1080x2400). All driving was done with adb (uiautomator dump for coordinates, screencap for checks). No accounts were signed in and no passwords were typed. The notifications permission was granted with `pm grant` because it was denied on this install.

## What failed

### Serious problems

None. A first reading of the code suggested that deleting the only category chosen for updates left its id in the filter, so the check would cover nothing. The settings file read from the emulator after that delete shows an empty `library_update_categories` set: `LibraryRepository.deleteCategory` removes the id from both the update filter and the notify-muted set. Not a bug.

No crashes, broken navigation, data loss or layout breaks were seen.

### Minor problems

2. MangaDex search failure ("This source returned an unexpected response") is not persisted: after restart, Sources shows no error line for MangaDex, while the MangaBuff and MangaRead lines are shown. Steps: global search "solo" → All sources → MangaDex shows the error; force-stop, relaunch, Menu → source row → Sources → MangaDex has no line. Cause not determined (probably a failure path that does not go through `SourceHealth`).
3. "Update categories" cannot be set to "no categories": unticking every box means "All categories". Only a UX point.
4. `ReadingSessionTracker.pause()` and `resume()` are never called from `ReaderViewModel` (dead code). The ON_STOP flush and the 2-minute idle cap cover the time, so there is no visible effect.
