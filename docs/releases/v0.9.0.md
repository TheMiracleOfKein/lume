# Lume v0.9.0

The local library now reads CBR, CB7 and PDF as well as image folders and CBZ.

## New

- **CBR and CB7 chapters.** Import a folder with `.cbr`, `.rar`, `.cb7` or `.7z` files the same way as `.cbz`: Settings → Library → Local files → Import folder. Lume recognises an archive by its contents, so a CBZ named `.cbr` still opens.
- **PDF chapters.** Each `.pdf` file is one chapter, with one page per PDF page. Pages are drawn on the phone at the width of the screen, work in every reader mode, and can be bookmarked. The first page is the cover.
- **Clear messages for files Lume can't open.** RAR5 archives (the newer RAR format) aren't supported yet; Lume says so and suggests repacking them as CBZ. A damaged archive shows "damaged or unsupported archive" instead of a crash or a technical message.

## Fixed

- **Two chapters with the same file name.** If two series each had a file with the same name (for example `04.cbz`), opening the second could show the pages of the first. A file replaced by a newer version could also keep showing its old pages. Each file now has its own unpacked copy.
- **Local chapters** no longer offer a download button: they are already on the phone.

## Updating

Install it over v0.8.1 as usual. Your library, progress, bookmarks and downloads are kept. The database doesn't change. Unpacked copies of local archives are made once more the first time you open each chapter.

## For developers

- `data/local/archive`: `ArchiveReader` with `ZipArchiveReader`, `RarArchiveReader` (junrar 8.1.2) and `SevenZArchiveReader` (Commons Compress with XZ for Java 1.12). `ArchiveReaders.open` picks one by magic bytes, with the extension as a fallback; `ArchiveReaders.isArchive` / `isChapterFile` replace the separate checks in `LocalImporter`, `LocalEngine` and `DownloadStore`. Entry names are checked against path traversal. RAR5 → `UnsupportedRarVersionException`, other failures → `DamagedArchiveException`.
- `ArchiveCache.dirKey` names unpacked folders after the path hash, change time and size (`local_zip/` and `cbz/`).
- PDF: `lume-pdf://<path>#<index>` page URLs (`PdfPageUrl`), Coil `PdfPageFetcher` and keyer, `PdfRendererPool` with one renderer per file behind a mutex and bitmaps capped at 8M pixels (`fitSize`). `domain/PageData.pageData(url)` replaces the `startsWith("http")` checks in the reader, `PageAnalyzer` and page bookmarks; tall-page slicing skips PDF pages.
- Offline parser tests (merged before this release): every engine splits fetching from parsing, with saved pages in `app/src/test/resources/fixtures`, recorded with `-Plume.live.record`.
- New tests: `ArchiveReadersTest`, `ArchiveCacheKeyTest`, `PdfPageUrlTest`, `PdfFitSizeTest`, `DownloadQueueGuardTest` and the per-engine parsing tests.
- Device check: [v0.9.0-check.md](v0.9.0-check.md). A real RAR5 file wasn't tried on the device.
