# v0.7.10 pre-release device check

Build: gate APK (`lume-gate.apk`, branch fix/safety-0.7.10) installed on emulator-5554 (Pixel 6a, API 37, 1080x2400) over a real v0.7.9 install with `adb install -r`. The build reports versionName 0.7.9 (versionCode 22), as the check brief said (no version bump in this build).

Tool: mobile-mcp for all UI driving (snapshot-first, element refs). adb for install, logcat, airplane mode, rotation settings and screenshots. One caveat: an adb `uiautomator dump` ran while mobile-mcp was driving; the two collided and produced a `FATAL EXCEPTION` in the uiautomator process itself (PID 9181, "UiAutomationService already registered"). That is not Lume. Lume's own log was clean (see "Crash check").

Screenshots from adb are kept in `$T/gate` (`A3_reader_after_upgrade.png`, `A3_reader_offline.png`, `G_reader_landscape.png`). The mobile-mcp screenshots are in the tool-results folder only.

## Changed areas checked

- Downloads: temp folder `.lume-part`, cancel/kill behaviour, queue writes.
- Restore and backup: one transaction, size caps (backup/restore path exercised; size caps not triggered).
- App update check: host, size and SHA-256 checks (update check runs; no update available, so the download path was not exercised).
- Lock screen: accessibility hiding (lock refused on this emulator, so the lock screen itself was not shown).
- Library update worker: stops on cancel (not exercised directly; "Update now" completed normally).
- Tracker token refresh: not testable (needs accounts). See "Not checked".

## Crash check

- `adb logcat -d | grep -A15 "FATAL EXCEPTION"` after the logcat clear that followed the gate install, and again at the end of the check: no entries (count 0), covering the force-stop relaunch, the restore, the reader and the rotation.
- The one FATAL EXCEPTION seen earlier, in the v0.7.9 phase, was the uiautomator process (PID 9181) from the adb dump collision described above. It was cleared by the logcat clear that followed the gate install. Lume was not involved.
- No ANR entries.

## Not checked

- Tracker token refresh: needs accounts, not used.
- Source pack id rejection: needs a hosted pack file.
- App update download (host, size, SHA-256): no newer release to download; only the "up to date" path ran.
- App lock with a screen lock set: the emulator has no screen lock, so the lock screen and accessibility hiding were not exercised.
- Cancel of a download that is already in progress (only a waiting one was cancelled).
- Backup save to a file in Downloads (system picker) and restore from a file.
- Full page walk of chapter 4 (only the first page checked).
- Release APK and signing (debug-signed gate build only).
- Library update worker cancellation (not triggered).
- Russian locale.

- Reader progress was recorded for "Gokko" chapter 1 and "Aishiteru" chapter 1.
