# Lume v0.9.10

Lume saves crashes on the phone so you can send them with a bug report. The backup format is now written down and kept stable, and two old gaps are fixed: TalkBack behind the menu, and search marks for titles saved from another source.

## New

- **Crash log.** If Lume closes because of a crash, the details are saved on your phone (the last 10). **About → Share log** hands the crashes, the recent errors from the error log, the app version, the Android version and the phone model to an app you pick, for example email or a bug report. About shows how many crashes are saved, and **Clear crash log** removes them.
- **Backup format documented.** The format of Lume's backup files is now described in `docs/BACKUP_FORMAT.md` in the repository. Every backup an older Lume made keeps loading, and tests check this for every format version. New backups always write their format version and date at the top.

## Fixed

- **TalkBack and the menu.** With the main menu open, TalkBack and other accessibility services move only through the menu. Before, they also read the screen and the bottom bar hidden behind it. They come back when the menu closes.
- **Search marks.** The library colour bar in search results now also shows for a title you saved from another source: one linked on the title screen (Sources), or one with the same name.

## Updating

Install it over v0.9.9 as usual. Your library, progress, bookmarks and downloads are kept. There are no database changes. Backups from every earlier version still restore.

## Privacy

The crash log stays in the app's private storage on your phone. Nothing is sent automatically: it leaves the phone only if you share it yourself, and you see the app it goes to. The crash log and the error log are also kept out of Android's cloud backup.

## For developers

- `data/CrashLog.kt`: a default uncaught-exception handler, installed first in `LumeApp.onCreate`, saves the crash (time, thread, version, stack trace up to 12,000 characters) to `files/crash_log.json` and then passes it to Android's handler. At most 10 crashes are kept. `CrashLog.report` builds the shared text.
- `docs/BACKUP_FORMAT.md`: every field, the version history and the compatibility rules. `BackupFormatTest` loads one saved sample per format version (`app/src/test/resources/backups/lume-v1.json` … `lume-v5.json`) and pins every field name and optional flag. `version` and `createdAt` use `@EncodeDefault`, so they are always written.
- `AppShell`: the NavHost and the bars sit in a box that gets `clearAndSetSemantics {}` while the menu is open.
- `domain/LibraryMarkIndex`: search marks are found by source and id, then by a linked source (`LibraryDao.observeLinkedTitleSources`), then by normalised name (3+ letters or digits).
- `.github/workflows/release.yml` (optional): builds, signs and checks a release APK from a tag with repository secrets, keeps it with a SHA-256 file as a workflow artifact, and publishes the release only if the tag has none yet. It runs on demand, or on every tag once the `LUME_RELEASE_FROM_CI` variable is `true`. Setup: `docs/RELEASING.md`.
- Tests: `CrashLogTest`, `BackupFormatTest`, `LibraryMarkIndexTest`.
