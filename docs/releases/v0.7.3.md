# Lume v0.7.3

MangaLib bookmark import works now, and it brings every folder, your own ones included.

## Fixes

- **Import bookmarks no longer fails with "Not a Lib source".** In v0.7.2 the import stopped right away on every MangaLib, HentaiLib and YaoiLib source. It now runs.
- **Every bookmark, whatever its folder.** The import asks the site for all bookmarks at once instead of folder by folder, so folders you made yourself on the site come along with "Читаю", "В планах", "Брошено", "Прочитано" and "Любимые". Each folder still becomes a Lume category of the same name.
- If the site's folder list can't be loaded, the built-in folders still get their names. Titles in one of your own folders are then imported without that folder's category.

## Updating

Install it over v0.7.2 as usual. Your library, progress, bookmarks and downloads are kept. No database changes.

## Known limits

- Read progress on the site (the last chapter read) isn't brought over yet; only the titles and folders are.
- Titles bookmarked on another Lib site are left out: import them from that site's source.
- The import needs a sign-in. A site that blocks your region blocks the import too.

## For developers

- `SourceRegistry` wraps every engine (`DispatchingSource`, `ImageHostTrackingSource`), so `sourceById(id) as? LibSocialEngine` was always null. Both wrappers now implement `WrappingSource`; `CatalogSource.unwrapped()` and `SourceRegistry.engineById(id)` reach the engine. `LibBookmarkImport` uses `engineById`.
- `LibSocialEngine.fetchBookmarks()` reads `/bookmarks?user_id=…&status=0`, where each entry names its folder in `status` (custom folders have large ids such as `2598197`). If that gives nothing, it falls back to reading folder by folder.
- `withDefaultLibFolders` names the built-in statuses 1–5 when `/bookmarks/folder/{userId}` doesn't list them. Paging also reads `meta.next_page_url`. New cases in `LibBookmarksTest`, one built from a real `status=0` answer.
