## Problems found

1. **MangaDex is unreachable on this emulator (broken, environment or region?).** Steps: Menu → Source → MangaDex, then open Catalog. The catalog shows the raw parser error "Unexpected JSON token at offset 11 … JSON input: <!doctype html> …" with a Retry button. Retry does not help. The emulator has working internet (ping OK). Severity: broken, probably caused by a block or proxy page on the network, not by the release. Still, the user sees a raw technical message. Severity of the message: cosmetic.
2. **Kotatsu test used a placeholder MangaDex link.** Because of Problem 1, I could not copy a real title URL from MangaDex. The import still worked, but the favourite's title is a made-up uuid. Opening that title is not verified. Re-run with a real link when MangaDex is reachable.
3. **Suspicious: chapters 1, 2 and 4 of "Gokko" (MangaKatana) start with the same page.** Chapter 1 (38 pages), chapter 2 (64 pages, downloaded as CBZ) and chapter 4 (online, 35 pages) all show the same first page. The CBZ's page 0000.jpg is the same image as the online reader's first page. This points to either the source serving the same first page or Lume's page mapping. Not confirmed. Severity: needs checking (would be broken if Lume's fault). Check against the MangaKatana site in a browser.
4. **Leftover `meta.json` after deleting a download (cosmetic).** After deleting chapter 1, the title folder `_manga_gokko.8057` still holds `meta.json`. Steps: download a chapter to the custom folder, delete it from Downloads, look at the folder. Severity: cosmetic.
5. **Folder names are slug-plus-id, not the title and chapter names.** Example: `_manga_gokko.8057/_manga_gokko.8057_c1`. This may be by design. Severity: cosmetic, the user may expect readable names.

No crashes, no ANRs, no leftover `.lume-part` files.
