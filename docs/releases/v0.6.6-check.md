# Lume v0.6.6: pre-release check

Branch `feat/source-filters`, diff `v0.6.5..HEAD` (24 files, +1302 / -77). Method: the full diff was read and the call sites of every new API were traced. Nothing was built, unit-tested, run on an emulator or sent to a live site. The findings below come from reading the code.

## What changed

**Mechanisms**
- `CatalogSource.loadFilters()` returns the site's own filter lists. The default is `getFilters()`. Engines cache the result per instance in `SiteFilters` (`EngineSupport.kt`), and a failed fetch is not cached.
- `CatalogSource.filtersWithQuery` (false for ReManga and Asura): a text search ignores the filters there.
- `CatalogSource.browseSections()` returns `BrowseSection`s, each a search with no text and preset filters (`Filters.kt`: `BrowseSection`, `choose()`, `include()`, `carryOver()`).
- `FilterList.carryOver()` keeps what the user already set when longer lists arrive. Filter ids inside site groups are `<group>:<site id>`.
- Engines changed: MangaDex, LibSocial (MangaLib, YaoiLib, HentaiLib), ReManga, Madara (theme search form), Asura, HiveToons, WeebCentral. Each has its own search query builder, site filter loader and browse sections.
- `TitleDetails` gains `year` and `score` (0 to 10). MangaDex asks `/statistics/manga/{id}` for the score.

**Screens, menus, buttons, animations**
- Search screen (`SearchScreen.kt`): the filter button (`prepareFilters`, which now loads the site lists with a 10 s timeout), the filter panel with Apply and Reset (`onApply` calls `applyFilters`), the note "This site filters only without search text" (ReManga, Asura, only when the search field has text), a spinner row "Loading the site's filters...", and load-more at the end of the current-source list.
- Filter panel (`ui/components/FilterPanel.kt`):
  - Sort and Select chips, Text fields (ReManga year; Madara author, artist, year).
  - Groups of checks or tri-states become chip groups. Each has a header with the group name, the chosen items as one accent line, and a "Show all (N)" / "Fold" toggle with an expand/collapse icon. Groups over 12 entries start folded (`FOLD_AT`). Groups over 30 entries get a Find field (`FIND_AT`) that filters chips by substring.
  - Check chips toggle. Tri-state chips cycle off, "+ include" (accent), "- exclude" (struck through, danger colour), off.
  - Animations: `AnimatedVisibility` with `expandVertically`/`shrinkVertically`, `animateColorAsState` on chip fill and border (`Motion.short`/`medium`).
- Catalogue (`CatalogScreen.kt`): on the Popular tab, a horizontally scrolling row of chips "Popular" plus one per browse section, shown only when the source has sections. Each section has its own list scroll position. The Latest tab is unchanged. A source or network change reloads the open section.
- Title screen (`TitleScreen.kt`): "By ..." and "Art: ..." lines, then one facts line "Type · year · ★ score" (any part may be missing).
- Strings: 36 new keys in `values/strings.xml` and `values-ru/strings.xml`, with the same key set in both (checked).

**Per source, from the code**
- MangaDex: genre, theme, format and content tag groups (tri-state, with "has all / any"), origin language (Manga, Manhwa, Manhua, Comic), status, sort. Sections: New titles, Top rated, Completed, Manhwa.
- MangaLib / YaoiLib / HentaiLib: types, status, genres and tags (tri-state), format (tri-state), "has all / any". Sections: Most viewed, Recently added, Completed (status id 2 is hard-coded).
- ReManga: types and genres (tri-state), tags (categories), age checks, year from. Filters only without text. Sections: Most viewed, Recently added.
- Madara (theme search form): genres (checks), status, adult, has all / any, author, artist, year. Sections: Trending, New, Top rated, Completed. Author, artist and year are sent with the text search.
- Asura: genres (checks), type and status selects, sort. Filters only without text. Sections: Top rated, Completed.
- HiveToons: genres (checks), type and status selects, sort. Sections: Recently added, Completed.
- WeebCentral: type and status checks, tags (tri-state), sort. Sections: Recently added, Completed, Manhwa.

## Check by hand

Phone with internet, app language English unless a step says Russian. Use Current-source search for the filter steps; global search runs without filters. Enable the sources MangaDex, MangaLib, ReManga, Asura, one Madara source, HiveToons and WeebCentral.

1. **Filter panel opens and loads (each source).** Search screen, active source X, tap the filter button.
   - Expected: a "Loading the site's filters..." row appears for a moment, then the groups appear. Opening never crashes or hangs.
   - Repeat for MangaDex, MangaLib, ReManga, Asura, a Madara source, HiveToons and WeebCentral.
2. **Site lists per source type.**
   - MangaDex: groups Genres, Tags, Format, Content, Type, Status, Content rating, and the "Several genres or tags" select. Genres are alphabetical.
   - MangaLib: Types, Status, Genres, Tags, Format, and "Several genres or tags".
   - ReManga: Type, Genres, Tags, Age (checks), and a "Released in or after (year)" field.
   - Madara: Genres (checks), Status, Adult, "Several genres or tags", Author, Artist, Release year.
   - Asura: Genres (checks), Type and Status selects.
   - HiveToons: Genres (checks), Type and Status selects.
   - WeebCentral: Type and Status checks, Tags (tri-state).
   - Expected: every group has entries; empty groups do not appear.
3. **Include and exclude chips (MangaDex, MangaLib, ReManga, WeebCentral).** In the Genres group, tap "Action" once.
   - Expected: "+ Action" with accent fill and border. Tap again: "- Action" struck through in red. Tap again: plain "Action".
   - Check groups (Madara genres, Asura genres, HiveToons genres, Type, Status): one tap ticks the chip; a second tap unticks it. No exclude state.
4. **Include plus exclude result.** On MangaDex include "Action" and exclude "Romance". Tap Apply with an empty search field.
   - Expected: results are titles with Action and without Romance. Open a few titles and check their genres.
   - Set "Several genres or tags" to "Has all", then to "Has any" with two included genres. Expected: the list grows with "any" and shrinks with "all".
5. **Fold and find.**
   - In a group with more than 12 entries (MangaDex Genres): the group starts folded, the header reads "Show all (N)", and the chosen items show on one line in accent colour.
   - Tap the header: it expands with an animation, the label reads "Fold". Tap again: it folds.
   - In a group with more than 30 entries (MangaDex Tags, WeebCentral Tags): a Find field appears above the chips. Type "fan": only chips containing "fan" (any case) show. Clear the field: all chips return.
   - Excluded items appear with a leading "-" in the folded header.
6. **Filters with and without search text.**
   - MangaDex, no text, one include: Search runs with the filter (the search button enables with filters only).
   - MangaDex, text "one", plus the same include: results match both the text and the genre.
   - ReManga or Asura, text "one", plus an include: the panel shows "This site filters only without search text: clear the field to use them." The results follow the text only.
   - ReManga or Asura, clear the text, Apply: results are filtered again. The note disappears.
   - Expected: no crash, no results from another source.
7. **Madara author, artist, year.** On a Madara source, type "Author name" in Author and Apply with an empty search field.
   - Expected: only titles by that author show. Year "2019" in Release year narrows results to that year.
8. **Browse section chips.** Catalogue, Popular tab, source MangaDex.
   - Expected: a row "Popular", "New titles", "Top rated", "Completed", "Manhwa" above the list. Tap "Top rated": the list changes and the chip is selected. Tap "Popular": the original list returns with its scroll position.
   - Scroll "Top rated" down and back up: the scroll position stays per chip.
   - Latest tab: unchanged, no chips.
9. **Switching sources.** Change the active source from MangaDex to Asura in Sources, then open Catalogue.
   - Expected: chips show Asura's sections ("Top rated", "Completed"). Titles match Asura.
   - A source with no sections (the local files source, or any engine not listed above): the chip row is hidden and the list is that source's Popular list. Then go back to a source with sections: the section chip that was selected before may still be selected. See the minor notes below.
   - Switch back to MangaDex: MangaDex sections return. A section open before the switch reloads.
10. **Title screen details.**
    - MangaDex title with an author and an artist: "By Name" line, then "Art: Name" if the artist differs. Facts line like "Manhwa · 2018 · ★ 8.7". The score may be missing if MangaDex does not answer; the line then has only type and year.
    - Asura title with a rating: "★ x.x" in the facts line.
    - A title with no author: no "By" line. No empty gaps, no overflow past two lines.
11. **Offline or slow site.** Airplane mode, open the filter panel on a source not yet loaded.
    - Expected: the spinner row stops after up to 10 s; the panel shows the basic filters (Sort, Status and so on). Turn the network on, open the panel again: the site lists load.
12. **Russian language.** Settings, language Русский, then the Search and Catalogue screens.
    - Expected: group names and buttons in Russian ("Жанры", "Теги", "Тип", "Формат", "Статус", "Все (N)", "Свернуть", "Найти", "Загрузка фильтров сайта…", "Одно нажатие включает, второе исключает."). ## Serious problems found

1. **FIXED in cf4a508: filters of the active source are sent to the results of another source (page 2+).**
   `SearchViewModel.kt:157`: `loadMore()` requests the next page from `currentSourceId` (the source that produced the results on screen) with `filters`, the panel's filters. `prepareFilters()` (`:174`) and `ensureFilters()` (`:208`) replace `filters` with the newly active source's list without touching `currentSourceId`.
   How it happened: search in source A, change the active source to B in Sources, come back to Search, tap the filter button (B's lists become `filters`), then scroll A's results to the end. Page 2 of A was requested with B's filter values (wrong option indices, B's text fields) and the titles were appended to A's list.
   Check of cf4a508: `searchCurrent()` now stores the filters it ran with (`currentFilters`, `SearchViewModel.kt:148`), and `loadMore()` requests with that copy (`:161`). The copy is safe: `FilterList` changes only through `updated()`, which returns a new list, so panel edits do not reach it. The page-2 case above no longer happens.
   Still open in the same function, not in cf4a508 and not new (the same code is in v0.6.5): `loadMore()` takes the query from the text field (`:157`), not from the search on screen. Type a new query without pressing search, then scroll the results to the end: page 2 of the new query is appended to the old results.

2. **FIXED in cf4a508: a browse section of the old source can show its titles under the new source.**
   `BrowseViewModels.kt:186-194`: the epoch collector clears the other section feeds (`stale.forEach { it.items = emptyList() }`) and sets `loadedOnce = false`, but does not cancel their jobs. A section load that is still running from the old source completes after the reset, and `CatalogFeed.load` (`:131`, `:134`) writes that source's `items` and sets `loadedOnce = true`. Later, tapping that chip calls `ensureLoaded`, which returns early because `loadedOnce` is set, and the list shows the old source's titles.
   Check of cf4a508: the collector now cancels each stale feed's `job` and clears its loading flags before the epoch bump (`BrowseViewModels.kt:194-201`). The loop has no suspension point, so no stale write can land between the cancel and the bump. A cancelled `withContext` in `DispatchingSource` (`SourceRegistry.kt`) drops its result instead of returning it. The open section reloads through the `LaunchedEffect` keyed on `sectionsEpoch` (`CatalogScreen.kt:82`).

3. **FIXED in 464fe77: the filter panel showed the previous source's filters and carried their states into the new source.**
   Before 464fe77, `SearchScreen.kt` opened the panel at once (`prepareFilters()` was no longer awaited) with `initial = vm.filters`, and `vm.filters` still held the previous source's lists: `ensureFilters()` assigned `filters` only after `loadFilters()` returned (up to 10 s). So the previous source's groups showed under "Loading the site's filters...". When the new lists arrived, `FilterPanel.kt` (`LaunchedEffect(initial) { draft = initial.carryOver(draft) }`) copied the previous source's states into the new list wherever the filter id matched. `carryOver` copies Check, TriState and Text states without comparing options, so Madara's `author`, `artist` and `release` text fields, and any shared genre id, carried over.
   How it happened: on Madara site A, set Author to "Jane" and tap Apply. In Sources make Madara site B active, go back to Search and tap the filter button. B's panel showed Author "Jane" once B's lists loaded, and Apply searched B by that author. Tapping Apply before B's lists arrived also lost the choices, because `searchCurrent()` replaced `filters` with B's static list while `filtersSourceId` was still A's.
   Cause: v0.6.5 awaited `prepareFilters()` before opening the panel, and `FilterPanel` used `remember(initial)`, which reset the draft when `initial` changed. v0.6.6 changed both.
   Check of 464fe77: fixed. `ensureFilters()` now sets `filtersSourceId`, `filters` and `defaultFilters` to the new source's static lists before its first suspension point (`SearchViewModel.kt:202-210`). `getFilters()` is synchronous and `activeSourceId` is a `StateFlow`, so the switch lands before the sheet composes. The draft is keyed on `sourceId` (`FilterPanel.kt:83`, passed at `SearchScreen.kt:117`), so no draft from another source survives, and `LaunchedEffect(initial)` only adds lists for the same source. Checked for regressions, none found:
   - Apply before the lists arrive keeps the choices: `searchCurrent()` finds `filtersSourceId == id` and returns at `SearchViewModel.kt:201`.
   - Lists arriving for the same source keep the user's choices: `loaded.carryOver(filters)` at `:222`, and the draft is carried over at `FilterPanel.kt:85`.
   - A late result for a source that is no longer active is dropped (`:220`).
   - No early return skips a needed load: a source reached with `load = false` keeps `filtersComplete = false`, so the next opening of the panel loads its lists.
   - Reset sets the draft to `defaults`, and Apply passes the draft to `applyFilters()` unchanged.

No new serious problems. This pass read the rest of `v0.6.5..HEAD`: all engines, `Filters.kt`, `Source.kt`, `SourceRegistry.kt`, `Models.kt`, `FilterPanel.kt`, `CatalogScreen.kt`, `BrowseViewModels.kt`, `TitleScreen.kt` and both `strings.xml` files. Every `R.string` and `R.plurals` reference exists in both locales, no resource name is duplicated, and every browse section id matches an option of the filter it sets.

Not serious, noted for the release owner:
- `CatalogScreen.kt:77-80`: the open section stays selected when the new source has no sections. The chip row is hidden, so the user cannot go back to "Popular", and the list shows the Popular feed of the new source under the old section's list state. The titles are correct.
- `EngineSupport.kt` (`SiteFilters`) and `CatalogViewModel.sections`: group and section names are fetched in one language and kept until the app restarts, so a language change leaves them in the old language.
- `SearchViewModel.kt` `prepareFilters()`: two overlapping calls set `filtersLoading = false` when the first one ends, so the spinner can hide while the second is still loading.
- `LiveSourcesTest.kt:106`: `loaded.include(genre.id)` passes a group id, which `include()` ignores, so the check always reports "filter ... ignored?". Test only, runs only with `-Plume.live`.
- `LibSocialEngine.kt` `browseSections()`: "Completed" uses status id 2 on every Lib site. Taken from a code comment, not verified against the sites.
- `SearchViewModel.kt:105`: `search()` tests `filtersActive` before `searchCurrent()` switches to the newly active source. After a source change, an empty-query search with the old source's filters still active runs the new source's unfiltered list, instead of doing nothing. Pre-existing in v0.6.5 (the old `ensureFilters` reset the filters the same way).
